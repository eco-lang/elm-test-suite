# Plan: generate the Lean translations of the tests, and Appendix A from one table

**Status (2026-11-09): implemented, phases 0 to 6** (see "Progress" at the end for what was done
and where the implementation differs from this plan). Phase 6's first step is done and its
remaining steps are a separate plan, [lean-encoding-widening.md](lean-encoding-widening.md). Revised before
implementation after an adversarial review (see "Review"). This plan is written to be implemented directly. Part A (Appendix A as data) comes
first, because the translator prints calls to the Lean functions Part A generates.

## Decisions

| Question | Decision |
|----------|----------|
| Language of the tools | Elm, run as `elm-pages` scripts |
| Lean in CI | No. Lean is built when the mechanisation stage (06) runs. A CI job may come later, skipping work by the input hashes the manifest records (B.10) |

## Goal

1. Every `elm-spec` test inside the fragment the Lean mechanisation encodes is translated into Lean
   by a program, from its source, so a translation cannot fall behind its test.
2. Every `elm-spec` test not translated has an exact, mechanical reason, shown on its page and
   counted on the site.
3. The derived forms of Appendix A exist once, as data, from which both the book's tables and the
   Lean functions are generated: the first step towards a SpecTec-style definition.

# Part A: Appendix A as data

## A.1 The template language (`DerivedForms/Term.elm`)

A row has two sides. The **derived** side is concrete syntax of the full language and is only ever
printed as LaTeX, so it is a list of pieces. The **equivalent** side is bare abstract syntax with
metavariables, from which both LaTeX and Lean are printed.

```elm
type Class = CExp | CAtExp | CPat | CAtPat | COp | CLab

type alias Meta = { cls : Class, name : String }
-- LaTeX macro by name: exp -> \expm, atexp -> \atexp, opv -> \opv, atpat -> \atpat,
-- pat -> \pat, lab -> \lab, valbind -> \valbind, topdec -> \topdec

type Ref
    = Plain Meta                 -- \atexp
    | Indexed Meta Int           -- \expm_1
    | Item Meta                  -- \expm_i: the i-th item of the row's sequence
    | ItemPrimed Meta            -- \expm'_i

type Piece                       -- derived side, and the equivalent side of computed rows
    = Kw String                  -- \kw{...}, the argument already escaped for LaTeX
    | M Ref
    | Seq SeqLayout (List Piece) -- the item pieces (with Item refs); printed per A.3
    | Break                      -- a new line of a [t] array
    | Text String                -- \text{...}
    | Raw String                 -- raw LaTeX (\;, \quad, \phantom{...}); used where today's layout needs it

type alias SeqLayout =
    { sep : List Piece           -- between items, e.g. [Kw ","]; [] for juxtaposition
    , sepAroundCdots : Bool      -- print sep on both sides of \cdots (df:list: "exp_1 :: \cdots :: exp_n")
    , showSecond : Bool          -- print items 1, 2 and n (df:if-chain, df:list-pattern) instead of 1 and n
    , breakBetween : Bool        -- each printed item on its own line of the array
    }

type Term                        -- equivalent side of a template row
    = TMeta Ref                  -- a metavariable of the row
    | TApp Term Term             -- Exp: exp atexp
    | TParen Term                -- AtExp: ( exp )
    | TOp Ref                    -- AtExp: ( opv ) for the operator a metavariable stands for
    | TOpLit String              -- AtExp: ( :: ), an operator written in the row
    | TVarQual String String     -- AtExp: Basics.negate
    | TConQual String String     -- AtExp in an expression, AtPat in a pattern: Basics.True
    | TVarOfLab Ref              -- AtExp: the variable spelt as the label
    | TLam Term Term             -- Exp: \ atpat -> exp
    | TCase Term (List ( Term, Term ))   -- Exp: case exp of pat -> exp ; ...
    | TNil                       -- AtExp [ ] in an expression, AtPat [ ] in a pattern
    | TRecordPat1 Ref            -- AtPat: { lab }
    | TPatCons Term Term         -- Pat: pat :: pat
    | TUse String (List Term)    -- another row applied: TUse "df:if" [c, t, e]
    | TNestRight NestRight
    | THole                      -- where the rest of the nesting goes

type alias NestRight =
    { item : Term                -- contains THole once
    , base : Term
    , wrapInner : Bool           -- each inner item (not the base) in TParen: df:if-chain
    , layout : SeqLayout         -- how the LaTeX shows it (A.3)
    , closers : Int              -- closing parentheses printed after \cdots (df:list-pattern: 2)
    }
```

Classes: `TApp`, `TLam`, `TCase` are `CExp`; `TParen`, `TOp`, `TOpLit`, `TVarQual`, `TVarOfLab` are
`CAtExp`; `TPatCons` is `CPat`; `TRecordPat1` is `CAtPat`; `TConQual` and `TNil` are atomic, `CAtExp`
or `CAtPat` by whether they are in an expression or a pattern position; `TUse` has the result class
of the used row; `TMeta` the class of its metavariable. Both printers check classes and insert the
coercions of A.4; a class error is a bug in the table, reported by the generator and its tests.

A row:

```elm
type alias Row =
    { label : String                     -- "df:if"; must match the book's \citelabel
    , block : Block
    , derived : List Piece
    , equivalent : Equivalent
    , condition : Maybe { text : String, space : String }   -- "n\\geq 2", "\\qquad" or "\\quad"
    , conditionOnOwnLine : Bool          -- today's df:if-chain puts it on its own array line
    , lean : LeanSpec
    }

type Block = Expressions | AtomicExpressions | AtomicPatterns | ValueBindings | Declarations | TopLevelDeclarations

type Equivalent
    = Template Term
    | Computed (List Piece)              -- LaTeX only; the Lean is hand-written

type LeanSpec
    = Generated
        { name : String                  -- e.g. "ifte"
        , params : List { name : String, ref : Ref, cls : Class }
        , result : Class                 -- CExp, CAtExp or CAtPat
        , seqParam : Maybe { name : String, items : List Meta }   -- one Meta: List T; two: List (T × U)
        , whenEmpty : Maybe Term         -- the result for an empty sequence, if not the fold's base
        }
    | HandWritten String                 -- where it lives, e.g. "Derived.lean: Def.fn and groupBind"
```

Checked against today's Lean: the generated `bin`, `ifte`, `andalso`, `orelse`, `neg`, `accessor`,
`access`, `listE` and `listP` are the same definitions; `lams` written with a `where`-local fold
still unfolds as `lams (p :: ps) e = .lam p (lams ps e)` by `rfl`, which `elmText_derivation`
relies on. `listE []` is `.atexp .nil` (hence `whenEmpty`); `listP []` is the base `.nil`;
`ifChain` for one arm equals `ifte`.

## A.3 Printing LaTeX (`DerivedForms/ToLatex.elm`)

- A block prints as today's: `\begin{derivedforms}`, one `\dform{\citelabel{<label>}<derived>}`
  `{<equivalent>}` per row, `\hline` between rows (not after the last), `\end{derivedforms}`.
- Pieces print literally: `Kw s` as `\kw{s}`, `M r` as its macro with subscript and prime, pieces
  joined by `\ ` unless the piece list says otherwise (`Raw`); `Break` makes the side a
  `\begin{array}[t]{@{}l@{}} ... \end{array}`.
- `Seq layout items` prints item 1, then (with `showSecond`) item 2, then `\cdots`, then item n,
  with `sep` between printed items and, with `sepAroundCdots`, on both sides of `\cdots`; with
  `breakBetween`, each printed item on its own line.
- A `Term` prints as concrete bare syntax with the book's spacing: application `f\ a`;
  `\kw{(}...\kw{)}` for `TParen`; `\kw{(}\opv\kw{)}` for `TOp`, `\kw{(}\kw{::}\kw{)}` for `TOpLit`;
  `\kw{Basics.True}`; `\kw{\textbackslash}p\ \kw{->}\ e` for `TLam`; `\kw{[ ]}`;
  `\kw{\kwlb}\ \lab\ \kw{\kwrb}` for `TRecordPat1`. `TUse` prints the **used row's derived form**
  with the arguments substituted (so `df:and`'s right column reads `if exp1 then exp2 else
  Basics.False`, as today). `TCase` prints its first rule on the `case` line and each further rule
  on a new line behind `\phantom{\kw{case}\ e\ \kw{of}}\ \kw{;}`, as today's `df:if`.
- `TNestRight` prints its items by its `layout` as `Seq` does, each item with the next in its hole,
  the base in the last hole; the parentheses an item opens in its hole are closed after the last
  item, `closers` of them as `\kw{)}\cdots\kw{)}` groups.
- The condition prints as `<space> (<text>)` at the end of the equivalent side, or on its own array
  line with `conditionOnOwnLine`.

**Target.** Inside the markers, the generated LaTeX must be identical to today's after collapsing
runs of whitespace, row by row. The printer and the row options are adjusted until it is. Any row
that cannot be made identical is listed in this plan's Progress section with today's and the
generated text, for the author to accept.

## A.4 Printing Lean (`DerivedForms/ToLean.elm`)

For each `Generated` row, one definition with the doc comment `/-- Row "<derived form in plain
text>": <equivalent in plain text>. -/`, in dependency order (a row before every row that uses it:
`bin`, `ifte`, then `andalso`, `orelse`, `ifChain`, `lams`, `neg`, `accessor`, `access`, `listE`,
`listP`). Terms print as constructors of `Syntax.lean`:

| Term | Lean |
|------|------|
| `TApp f a` | `.app <f as Exp> <a as AtExp>` |
| `TParen e` | `.paren <e as Exp>` |
| `TOp r` / `TOpLit s` | `.op <r>` / `.op "s"` |
| `TVarQual "Basics" "negate"` | `.var basicsNegate` |
| `TConQual "Basics" "True"` | `.con basicsTrue` (an AtExp or an AtPat; both constructors are `con`) |
| `TVarOfLab l` | `.var ⟨none, l⟩` |
| `TLam p e` | `.lam <p as AtPat> <e as Exp>` |
| `TCase e rules` | `.caseE e (.mk (.mk p1 b1) (some (.mk ... none)))` |
| `TNil` | `.nil` |
| `TRecordPat1 l` | `.record (some (.field l none))` |
| `TPatCons p q` | `.cons <p as Pat> <q as Pat>` |
| `TUse row args` | a call of that row's function, e.g. `ifte e1 e2 (.atexp (.con basicsFalse))` |

Coercions: AtExp to Exp is `.atexp x`; AtPat to Pat is `.atpat x`; Exp to AtExp and Pat to AtPat
are never inserted (the table must say `TParen`), and are reported as table errors.

`TNestRight` over the sequence parameter prints as a `where`-local recursion:

```lean
def ifChain (arms : List (Exp × Exp)) (e : Exp) : Exp := go arms
where
  go : List (Exp × Exp) → Exp
    | [] => e
    | [(c, t)] => ifte c t e
    | (c, t) :: rest => ifte c t (.atexp (.paren (go rest)))   -- wrapInner
```

Without `wrapInner`, the last two cases are one: `| x :: rest => <item with go rest in the hole>`.
With `whenEmpty`, the outer function matches `[]` first and returns it.

## A.5 Where the generated text goes

The generator rewrites **regions between marker lines** and leaves the rest of each file. It fails
if a marker is missing or duplicated.

- `definition/tex/appendix-derived-forms.tex`: each of the six `derivedforms` blocks is enclosed in
  ```
  % BEGIN GENERATED derived-forms:<Block> (definition/tools/src/GenerateDerivedForms.elm); edit the table, not this
  ...
  % END GENERATED derived-forms:<Block>
  ```
  Figures, captions, headings and prose stay hand-written outside the markers. The file still holds
  the `\citelabel{df:...}` lines, which `runner/spec-items.js` and `runner/definition-data.js` read
  (neither follows `\input`, so the tables are not split into files).

  (which call `neg`) and `A`. The generated functions use only `Syntax.lean` constructors,

  `bin`, `ifte`, `andalso`, `orelse`, `lams`, `neg`, `listE`, `accessor`, `access`, `listP` are

# Part B: the translator

## B.1 Which tests

Every `.elm` file under `tests/*/src/` that has `elm-spec` among its `-- TAGS:`, is not a helper
(`-- HELPER:`) and defines a top-level `main`. Order: project name, then file name, by code point.

## B.2 Directives (`Translate/Directives.elm`)

Read from the source text (the parser drops comments):

| Directive | Treatment |
|-----------|-----------|
| `-- TAGS:` | tags |
| `-- CHECK: <label>: <value>` | split at the **first** `": "`; a label containing `": "` makes the test refused `checks:label-colon` |
| `-- CHECK: <text>` with no `": "` | refused `checks:unlabelled` |
| `-- CHECK:` containing `{{` | refused `checks:regex` |
| `-- CHECK-NOT: <label>:` (nothing after the colon) with `-- EXIT: 1` | the label expects no value |
| `-- CHECK-NOT:` otherwise | refused `checks:check-not` |
| `-- EXIT: <n>` | noted (only `1` with a CHECK-NOT, or `0`, is accepted; otherwise `checks:exit`) |
| `-- COMPILE-ERROR:` | refused `compile-error` |
| `-- FLAGS:`, `-- STDIN:`, `-- STDIN-DELAY-MS:`, `-- ENV:`, `-- UNSETENV:` | refused `effects` |
| `-- CHECK-NEXT:`, `-- CHECK-SAME:`, `-- CHECK-DAG:`, `-- CHECK-LABEL:` | refused `checks:directive:<name>` |
| `-- XFAIL:`, `-- LINUX-ONLY:`, `-- NO-CACHE:`, `-- MODE-GUARD:`, `-- NO-SKIP:`, `-- UNICODE:`, `-- HELPER:` | ignored (they concern running the test, not its meaning) |

The runner matches a CHECK line as a substring of the output; Lean compares the printed value with
the CHECK value exactly. A test whose output line has more than its CHECK value will disagree in
`run-examples` (phase 4). The disposition is to make the test's CHECK line exact, which improves the
test, or to record the check in `knownDiv` with the reason.

## B.3 Parsing

`Elm.Parser.parseToFile source`. In elm-syntax 7.3.9 this applies the precedence and associativity
of elm/core's operators itself (the table is in `Elm.Parser.Expression`). A parse failure is refused
as `parse`; four tests are known to fail (see "Where things stand").

**Literal text.** `Integer Int`, `Hex Int` and `Floatable Float` hold JavaScript numbers, which
lose precision beyond 2^53. The translator slices each literal's text from the source by the node's
range (rows and columns 1-based; a literal is on one line) and parses the text
(`Translate/Literal.elm`): hex `0x...` as an unsigned integer; float text `d.ddd[e[+-]ddd]` as
`(m, e)` with `m` the digits without the point (leading zeros removed, at least one digit kept) and
`e` the written exponent minus the number of digits after the point: `0.5` is `(5, -1)`, `1e300` is
`(1, 300)`, `1.50` is `(150, -2)`. A negative number in the source is `Negation (Integer n)`.

## B.4 The fragment (`Translate/Scope.elm`, `Translate/Fragment.elm`)

**Imports and names.** An import is accepted if its module is `Html` (any exposing) or is one of
the default imports restated: `Basics`, `List`, `Maybe`, `Debug`, `Char`, `String`, `Tuple`,
`Result` (any exposing; whether the names it brings in may be used is decided by name resolution
below). Any other import is refused `import:<Module>`.

Name resolution of every variable, constructor and operator occurrence: a local binding (pattern,
`let`, top-level, a copy) first; then the names E0 binds (B.6), unqualified or qualified as listed;
then names an import exposes, which resolve to `<Module>.<name>`. `text` and `Html.text` resolve to
`Html.text`, which is accepted only as the whole `in` part of `main`'s `let` (B.5).

The checks run in this order; the first that fails gives the refusal, with the source range:

1. Directive refusals (B.2): `compile-error`, `effects`, `checks:*`.
2. `effects`: a `port` declaration or `port module`; any name resolving into `Platform`,
   `Platform.Cmd`, `Platform.Sub`, `Task`, `Process`, `Browser`, `Html.Events`, `Json.Decode`,
   `Json.Encode`.
3. `import:<Module>`.
4. `construct:<name>`: `glsl`; `float-pattern`; `record-alias-constructor` (a type alias of a record
   used as a value); `tuple-arity` (tuples other than 2 or 3, and patterns likewise);
   `infix-declaration`; `lone-surrogate` (a string or char literal with a surrogate escape: Lean
   strings hold only Unicode scalar values); `main-shape` and `check-shape` (B.5).
5. `basis:<Module.name>`: a name that resolves to nothing in E0 (B.6), by its resolved qualified
   name: `basis:Basics.toFloat`, `basis:String.fromInt`, `basis:List.map`; `++` is
   `basis:Basics.append`.
6. `checks:unmatched:<label>` (B.5).
7. `type:<detail>`: inference fails to unify (B.7). It should not happen for programs Elm accepts,
   but 17 `elm-spec` tests are not accepted by Elm 0.19.1, and some are the hard cases of inference;

## B.5 Extracting the program (`Translate/Extract.elm`)

- **`cons`**: for each `CustomTypeDeclaration`, each constructor `(name, number of arguments)`, in
  source order.
- **`defs`**: each top-level `FunctionDeclaration` other than `main`, as `Def.fn name args body`,
  and each top-level `Destructuring p e` as `Def.pat p e`, in source order. Type aliases and
  annotations are used by inference only.
- **`main`** must be a `FunctionDeclaration` with no arguments whose expression is a
  `LetExpression` whose `in` part is `Html.text <string literal>` or `text <string literal>` with
  `text` exposed by `import Html`; otherwise `construct:main-shape`.
- **`checks`**: each declaration of `main`'s `let` of the form
  `LetDestructuring AllPattern (Application [FunctionOrValue ["Debug"] "log", Literal label, arg])`,
  in order, `arg` with one `ParenthesizedExpression` unwrapped (Lean's `debugLog` adds those
  parentheses back). Other forms of logging (`|> Debug.log`, `Debug.log label <| e`) are
  `construct:check-shape`.
- **`locals`**: every other declaration of `main`'s `let`, in source order.
- **Expected values**: each check has exactly one CHECK or CHECK-NOT line with its label, and each
  such line exactly one check; otherwise `checks:unmatched:<label>`. A CHECK-NOT label expects
  `(no value)`.
- **Kind of each check**: from inference (B.7), the type of `arg` after specialisation: `int`
  (Int), `float` (Float), `string` (String), `char` (Char), `data` (Bool, Order, `Maybe`, `List`, a
  custom type, a tuple, a record), `function`. It is written into the program (B.9) and decides
  whether the kernel can check it (B.11).

The phrase for a check is, as today, `letDefs defs (letDefs locals (debugLog label arg))`: each
check is evaluated on its own, with all of `main`'s other declarations in scope, and every local is
evaluated for every check. So a test with a local that has no value would give no value for every
check in Lean, while Elm prints the checks before it; such a test disagrees in `run-examples`
(phase 4) and is recorded in `knownDiv` with that reason. None is known today.

## B.7 Types and inference (`Translate/Types.elm`, `Translate/Infer.elm`)

Needed from types: the type, Int or Float, of every integer literal; the instance at which every
variable occurrence uses a declaration with a `number` variable; and the type of each check (its
kind, B.5).

```elm
type Type
    = TVar Int
    | TCon String (List Type)            -- "Int", "Float", "Bool", "Char", "String", "Order", "List", "Maybe", user types
    | TFun Type Type
    | TTuple (List Type)                 -- 0 (unit), 2 or 3 components
    | TRecord (Dict String Type) (Maybe Int)   -- fields, and the row variable if extensible

type Class = Any | Number | Comparable | Appendable | CompAppend

type alias Scheme = { quantified : List Int, t : Type }

type alias State =
    { next : Int
    , subst : Dict Int Type
    , classes : Dict Int Class
    , literalTypes : Dict RangeKey Type
    , occurrences : Dict RangeKey Occurrence
    , checkTypes : Dict String Type      -- by check label
    }

type alias Occurrence = { binder : BinderId, instance : Dict Int Type }   -- quantified var -> type here
```

- **Algorithm**: Hindley-Milner with let-polymorphism, algorithm J (unification with the
  substitution threaded through `State`). A variable of class `Number` meeting `Int` or `Float`
  binds; two variables merge to the more specific class (`Number` over `Comparable` over `Any`).
  Records unify their common fields and bind each side's row variable to the other side's extra
  fields; closed records need equal field sets. **Any unification failure stops inference and
  refuses the test `type:<the two types>`.**
- **Literals**: an integer literal (decimal or hex) gets a fresh variable of class `Number`
  (r:s-atexp-scon: `typeof` of an integer constant is `∀number. number`); a float literal is
  `Float`; a char `Char`; a string `String`. In a pattern an integer constant is `Int`
  (r:s-atpat-scon).
- **Annotations**: converted to `Type`, expanding type aliases with their parameters; a type
  variable name gives the class its name says (`number...`, `comparable...`, `appendable...`,
  `compappend...`, else `Any`). An annotated binding has its annotation as scheme and may be used
  polymorphically in its own body; an unannotated one is monomorphic within its own group.
- **Declaration groups**: the declarations of each `let`, and the top-level declarations, are split
  into components by the same "refers to" relation as `Derived.lean`'s `components`, and inferred
  component by component in that order; each component is generalised before the next. **Pattern
  bindings are generalised like the others**: the book's closure applies to every group of value
  bindings, pattern bindings included (static-core, r:s-valbind-pat), and Elm accepts
  `let (a, b) = (1, 2)` with `a` used at Int and at Float. **A group is closed as one** (ruling A93,
  static-core sec:static-core-closure): each binding's scheme is closed also over the `number`
  variables of the other bindings of its group that its own type does not mention.
- **Custom types**: each constructor's scheme from its declaration (`∀params. arg1 -> ... -> T
  params`).
- **`main`**: its `let` is one scope; the check expressions are inferred in it as further
  declarations `_ = Debug.log ...` of that `let`, and each check's type is recorded by its label.
- **Recording**: at each integer literal, its type; at each occurrence of a variable bound by a
  `let` or top-level declaration, the binder and the instantiation of the binder's quantified
  variables. An occurrence inside the binder's own (unannotated) group is recorded with the
  **identity** instantiation: it refers to the same copy as the group it is in.

Unit tests (`tests/InferTest.elm`): a literal under `/` is Float, under `//` Int, alone in
`Debug.log` defaulted Int; through a record field; through an annotated `number` function used at
Int and Float; through `List` and `Maybe`; through a lambda; a pattern binding used at Int and
Float; mutual recursion in one group; polymorphic recursion with an annotation; a unification
failure gives `type:`.

## B.8 Number specialisation (`Translate/Specialise.elm`)

> **Revised 2026-11-10.** Ruling A27 now makes a free `number` variable Float, and the default copy
> is the copy at Float (`Specialise.defaultNum`); where this section says Int for the default, read
> Float. `abs` at Int is now its copy `abs$Int`.

The book's procedure (dynamic-core, sec:dynamic-core-numbers): each declaration whose bindings'
schemes quantify `number` variables is replaced by its **default copy** (every such variable Int,
under its own names) and **one copy per other assignment** of Int or Float at which the program uses
it, binding new names; each occurrence refers to the copy for its instance; copies are made from the
outside in; a `number` variable left free in the program is Int (A27).

A declaration here is a group (a component, B.7); its `number` variables are the union of the
quantified `number` variables of its bindings, in a fixed order (binding order, then variable
order).

```
specialiseScope ρ groups body:         -- ρ : number var -> Int | Float, from enclosing copies
  needed := for each group g, { default(g) }      -- the default copy always exists (A59)
  repeat
    for each group g and assignment A in needed[g] not yet translated:
        translate g's right-hand sides under ρ ∪ A (specialising inner lets recursively)
        for each occurrence found of a binder of a group h of this scope:
            add resolve(ρ ∪ A, occurrence, h) to needed[h]
    translate body under ρ; add its occurrences likewise
  until nothing is added
  emit, for each group in order: the default copy, then the other copies by assignment
  (Int < Float, compared variable by variable)
```

The scopes: the top-level declarations, whose body is `main`'s `let`; `main`'s `let`, whose
declarations are the `locals` and whose body is **all the check expressions together** (so a copy
any check needs is made once and shared by every check's phrase); and every `let` inside them.

- `resolve(ρ, occurrence, h)`: for each `number` variable of group `h` (every binding of `h`
  quantifies all of them, A93), take its type at the occurrence (inference substitution applied),
  replace variables in ρ by their assignment, and read Int or Float. A variable the occurrence does
  not fix (a fresh instance of one its binding's type does not mention, or one left free in the
  program) is Int (A93, A27). Any result other than Int or Float refuses the test `number`. Unit
  test: `StandardA93MutualNumberDefaultTest` gives `f 3` the copy with `b` Int.
- **Names**: the default copy keeps its names. Another copy appends to every name it binds `$` and
  the assignment, one word per `number` variable of the group: `incF$Float`, `f$Int$Float`. For a
  pattern binding, every variable the pattern binds is renamed. `$` cannot occur in an Elm
  identifier, so the names cannot clash.
- Occurrences inside a copy are renamed by their own resolution; this handles recursion and
  polymorphic recursion. A group has at most 2^k copies for k `number` variables, so the loop ends.
- A literal's type is resolved the same way under the ρ of the copy it is in: Int prints as an Int
  constant, Float as `intF`.

Unit tests (`tests/SpecialiseTest.elm`): a declaration used at Int and Float gets two copies; an
unused one keeps its default copy; `incF 0.5` from `StandardCoreEvaluationExamplesTest` gives
`incF` and `incF$Float`, the occurrence referring to the latter; recursion at a second instance; a
pattern binding used at Float; two checks needing the same copy of a local get one copy.

## B.11 Lean integration

- **Build wiring.** `StandardElmMech.lean` imports `StandardElmMech.Generated.All` and every
  `StandardElmMech.Generated.Checks<Shard>` (the translator rewrites a marked region of
  `StandardElmMech.lean` listing them). `lakefile.toml` gets
  `[[lean_exe]] name = "dump-phrases" root = "DumpPhrases"` and
  `[[lean_exe]] name = "golden" root = "Golden"`.
- **Selection in one place.** Replace `floatValued` and the selection inside `#kernel_checks` by
  `kernelCheck? (p : Program) (ck : Check) : Option Expect` in `Theorems.lean`:
  - known divergence (`knownDiv`): `none`;
  - `kind = .int`: `expectOf` must give `.int`, else `none`; `.string`: `.str`; `.data`: `.con`
    when `expectOf` gives `.con` (a constructor without arguments), else `none`;
    `.float`, `.char`, `.function`: `none`;
  - `kind = .unknown` (hand programs): today's rule, `floatValued` then `expectOf`.

  This stops a float that prints `NaN`, `Infinity` or `3` from being read as a constructor or an
  Int and given an unprovable theorem.
- **Per-shard theorems.** `#kernel_checks <list> "<prefix>"` takes a term and a prefix, uses
  `kernelCheck?`, and names theorems `kc_<prefix>_<n>`, `n` counting from 0 in the list. Until
  phase 4 the argument-less form stays, over today's `allPrograms`. In phase 4, when `allPrograms`
  changes (below), it is replaced in `Theorems.lean` by `#kernel_checks handPartial "Hand"`, so
  that no check gets two theorems.
- **Derivable, per shard.** In each `Checks<Shard>.lean`:
  `theorem derivable_<Shard> : ∀ p ∈ shard_<Shard>, ∀ ck ∈ p.checks, ck.expected ≠ "(no value)" →
  ¬ knownDiv.contains (p.name, ck.label) = true → ∃ v, EvalExp p.env (p.phrase ck) v ∧ showElm v =
  ck.expected`, proved as `coverage_derivable` is today (`native_decide` on a Boolean function, then
  `checkShow_sound`). Per shard, so touching one test rebuilds one file. `Theorems.lean` gets the
  same theorem for `handPartial`, `derivable_Hand`. `corpus_derivable`, `rulings_derivable`,
  `coverage_derivable` (and `corpus_ok`, `rulings_ok`, `coverage_ok`) stay, over the hand lists,
  until those lists are deleted in phase 5, and are deleted with them; from phase 4 the site no
  longer refers to them.
- **allPrograms.** In phase 4, `allPrograms := generatedPrograms ++ handPartial`, where
  `handPartial` holds hand translations of tests the translator refuses but which are translated in
  part by hand (today only `pA48MinMaxNan`, refused `basis:Basics.isNaN`). The hand lists
  `corpus`, `rulings`, `coverage` stay in `Examples.lean` for `golden` only, out of `allPrograms`,
  so no check is proved twice; they are deleted in phase 5.
- **run-examples.** `Main.lean` iterates `generatedShards` and then `handPartial`, computes each
  check's theorem name from `kernelCheck?` and the shard numbering, and writes two files itself
  (`IO.FS.writeFile`): `definition/mechanisation/example-run.md` (as today, grouped by shard) and
  `definition/mechanisation/example-run.json`: for each check `program`, `project`, `shard`,
  `label`, `expected`, `kind`, the definition's value(s), `status`, `theorem` (`kc_<Shard>_<n>` or
  null) and `skipped` (`divergence`, `float`, `value` or null).
- **golden** (`Golden.lean`, phase 3): for each program of `corpus ++ rulings ++ coverage` with a
  generated program of the same name, print every check whose label or expected value differs, or
  whose `norm (phrase)` differs, comparing `repr` strings. `norm` removes parentheses that do not
  change meaning: `.atexp (.paren e)` in an Exp position becomes `e`; `.paren (.atexp a)` becomes
  `a`; in patterns, `.atpat (.paren p)` becomes `p` and `.paren (.atpat a)` becomes `a`. Exit status
  1 if any difference is not in the accepted list.
- **Accepted differences**, listed in `Golden.lean` with the reason, for which `run-examples` must
  still give the same value:
  - specialisation copies the hand translation did not make (`incF` and `incF$Float` where it wrote
    only the Float version);
  - literal types the hand translation chose where the book defaults to Int (`p = ( nan, 1 )` in
    CompilerIssue2362NanTupleEqualityTest and `inner = ( nan, 1 )` in
    CoreIssue988NanContainerSelfEqualityTest were written `fI 1`; the translator gives the default
    copy's Int);
  - parentheses the source has and the hand translation left out, where `norm` does not remove them.
- **Build time**: after phase 4, record `lake build` from clean and after touching one test. If a
  clean build takes more than 15 minutes, limit `#kernel_checks` to the `Elm*` shards and leave the
  rest to the `derivable_` theorems.

# Risks

- **Number specialisation.** A wrong choice may not change what a check prints. Defences: unit
  tests, `golden` on 54 tests, and the copies' names showing in the translation.
- **Inference on tests Elm rejects** (17 known): refused `type:`, never guessed.
- **Lean build time** at a few thousand theorems (B.11 gives the fallback).
- **Printing.** `showElm` must print as Elm's `Debug.log`; CHECK lines are substrings while Lean
  compares exactly (B.2).
- **Shared locals** are evaluated for every check (B.5).

# Out of scope

Tests expecting compile errors (they need the static semantics mechanised), modules, effects and
programs (Chapters 7 to 9), a DSL for the rules themselves (only Appendix A here), and a CI job
that builds Lean.
